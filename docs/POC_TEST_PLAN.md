# Veriff POC 테스트 계획

이 POC로 답해야 할 질문은 "Rocket Now Partner 라이더 온보딩·재인증에 Veriff를 쓸 수 있는가"입니다.
SDK 연동 자체는 끝났으므로, 아래 항목을 실제 기기와 실제 일본 신분증으로 채워서 도입 여부를 판단합니다.

## 0. 선행 조건 (막혀 있으면 이후 단계 불가)

- [ ] 풀 인증 결정(approved/declined)이 앱 상태 카드까지 도착한다
- [ ] Veriff에서 Biometric Authentication이 활성화되고 서버에 `VERIFF_AUTH_API_KEY`, `VERIFF_AUTH_SHARED_SECRET`이 설정된다
- [ ] 테스트용 integration인지 실서비스(live) integration인지 확인한다 (자동 판정 여부가 다를 수 있음)

## 1. 기능 검증

| # | 시나리오 | 기대 결과 | 결과 | 메모 |
|---|---|---|---|---|
| F1 | 운전면허증으로 풀 인증 | approved, `enrolled: true` | | |
| F2 | 마이넘버카드로 풀 인증 | approved | | |
| F3 | 재류카드로 풀 인증 | approved, 체류자격·취업 가능 여부가 웹훅에 포함되는지 | | |
| F4 | 신분증 일부를 가리고 촬영 | resubmission_requested + 사유 표시 | | |
| F5 | 다른 사람 셀피로 풀 인증 | declined | | |
| F6 | 승인된 회원이 본인 셀피로 재인증 | approved | | |
| F7 | 승인된 회원 ID로 다른 사람이 재인증 | declined | | |
| F8 | 미등록 회원 재인증 시도 | 앱에서 버튼 비활성화 | | |
| F9 | SDK 도중 취소 | 앱에 취소 표시, 이후 abandoned/expired | | |
| F10 | 인증 화면 일본어 표시 | 모든 안내 문구가 일본어 | | |
| F11 | 서버 재시작 후 상태 조회 | 결과 유지 (SQLite) | | |

## 2. 측정 항목 (라이더 5명 이상, 서류 종류별)

앱 하단 **측정 기록** 카드가 실행마다 SDK 진행 시간, 시작→접수, 접수→결정 시간을 자동으로 남깁니다(기기에 최대 50건 저장).
복사 버튼을 누르면 Markdown 표로 복사되니 이 문서에 붙여넣으세요. 접수·결정 시각은 서버 시계라 기기 시계와 몇 초 차이가 날 수 있습니다.

| 항목 | 측정 방법 | 목표(초안) | 결과 |
|---|---|---|---|
| 촬영~제출 소요 시간 | SDK 시작~`Status.done`까지 스톱워치 | 3분 이내 | |
| 제출~결정 소요 시간 | `submitted` 이벤트~decision 웹훅 시각 | 5분 이내 | |
| 자동 승인 비율 | approved / 전체 제출 | 90% 이상 | |
| 재제출 요청 비율 | resubmission_requested / 전체 | 10% 이하 | |
| 재인증 소요 시간 | 셀피 촬영~결정 | 1분 이내 | |
| 저사양·야외 환경 성공률 | 오래된 Android 기기, 야외 역광 | 기록 | |

## 3. 비기능·계약 확인

- [ ] 건당 비용 (풀 인증 / 재인증 각각), 최소 계약 물량
- [ ] 데이터 보존 기간, 저장 지역, 삭제 요청 처리 (일본 개인정보보호법 APPI)
- [ ] 웹훅 원본에 담기는 필드 목록과 서버 보관 정책
- [ ] SLA, 장애 시 연락 체계
- [ ] 커스텀 인트로 화면(`useCustomIntroScreen`) 사용 가능 여부
